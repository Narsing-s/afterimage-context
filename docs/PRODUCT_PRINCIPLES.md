# Afterimage Product Principles

## The primitive

Afterimage is built around one primitive:

**Memory → Return condition → Context → Relevance → Feedback → Resurface**

A reminder asks *when?* Afterimage asks *when will this matter again?*

## Product rules

1. **Relevance beats frequency.** A memory should return because the situation returned, not because a timer fired.
2. **Quiet is a feature.** No match is a successful outcome when context is unrelated.
3. **The user remains the authority.** Every resurfacing can be confirmed, snoozed, or marked outdated.
4. **Explain every return.** The interface should expose why a memory returned.
5. **No silent rewriting.** The system should never change a user's memory without an explicit action.
6. **Local-first by default.** Early functionality should work without a network request.
7. **Portable memory.** Users should be able to export and eventually import their data.
8. **No engagement traps.** No streaks, feeds, unread counters, or artificial urgency.
9. **Avoid overclaiming.** Afterimage is an experiment in context-based memory, not a claim that nobody else has explored adjacent ideas.

## Adaptive lifecycle

- **Active** — eligible to return.
- **Confirmed** — the user says the memory remains useful.
- **Outdated** — the user says it is no longer true.
- **Archived** — intentionally retained but excluded from resurfacing.
- **Snoozed** — temporarily quiet for a defined period.

Resurfacing history and confidence influence ranking, but they never override explicit user controls.

## Future context sources

Potential context signals include browser activity, app/category activity, calendar topics, location categories, documents, and user-entered context. Each signal must be opt-in, explainable, revocable, and privacy-preserving.
