# Afterimage Product Vision

## Positioning

**Afterimage is a contextual memory layer for your future self.**

It is not a calendar reminder, notes app, or generic chatbot. A memory is attached to a return condition and should resurface when the current context makes it relevant.

## The product loop

```text
Capture → Return condition → Context → Relevance → Feedback → Resurface → Learn
```

## What is new in the product direction

### Future Self Inbox
A dedicated view for memories that are active, confirmed, fading, or ready for review. Users can confirm, update, archive, or mark a memory as no longer true.

### Decision Memory
Important choices can preserve the decision, reasoning, alternatives, and eventual outcome. This creates useful decision history instead of isolated notes.

### Explainable resurfacing
Every resurfaced memory should answer **why am I seeing this?** The explanation should expose the relevant context, matched terms/signals, confidence, and the return condition that was used.

### Memory evolution
A memory is not permanent truth. Confirmations, outdated decisions, resurfacing history, and conflicts should help users see how their thinking changes over time without silently rewriting history.

### Privacy boundary
The product remains local-first. Context sources must be opt-in, explainable, revocable, expiring, and locally processed wherever practical.

## Real-time use cases

- Re-open a hosting comparison and recover the reason behind a previous infrastructure choice.
- Revisit a software architecture decision and see the original trade-off before changing it.
- Compare a product category and recover a previous purchase lesson.
- Prepare for a recurring meeting and review previous decisions connected to the topic.
- Revisit a travel plan and recover hotel, route, or budget preferences.

## Viral product loop

The product should create useful moments first and sharing second:

```text
Useful resurfacing → insight → optional share card → discovery → new user
```

Public sharing must be explicit. Private memories are never published automatically.

## Roadmap

1. Future Self Inbox
2. Decision Memory
3. Context explanation / "Why this returned"
4. Browser extension with user-initiated capture
5. On-device semantic matching
6. Calendar and GitHub integrations with explicit permissions
7. Encrypted cross-device sync
8. Shareable non-sensitive Afterimage cards
9. Memory evolution and decision timeline

## Product principle

> **The app should disappear until the moment your past becomes useful again.**
